# v0.6.0 design: single HACS-installable integration

Status: revision 3, implemented, awaiting sign-off (2026-09-20). Target: HA 2026.9.x minimum, Voice Satellite 2026.9.7+.
Reviewer's rounds 1 and 2 shaped every section below; the code in `custom_components/echo_experience/` is the
reference, this document records the decisions and their reasons.

## Goal and non-goals

One HACS custom repository replaces the SMB copy, `deploy.py` and the generated stop automation. Live behaviour is
unchanged except the two items under "Behaviour changes". No changes to Voice Satellite, Kiosk, Music Assistant or
the agents. Issues #1 and #2 stay open. Issue #3 closes only after the owner's live latency acceptance step.
Profiles remain in `echo_experience.json`; the UI subentry flow and a diagnostics download are deferred.

## 1. Frontend (`frontend.py`)

Static path `/echo_experience` → package `www/`, registered once per runtime (guard in `hass.data`, `RuntimeError`
on duplicate swallowed). Resource `/echo_experience/echo-experience.js?v=<manifest version>` in the storage
resources collection: `async_get_info()` first, then create/update; any `/local/echo-experience/echo-experience.js`
resource is deleted so a single card class registers. YAML resources: `add_extra_js_url` plus repair issue
`resources_yaml` when the legacy entry is present (no mutation API exists). Card file moved into the package; CI and
README paths updated.

## 2. Dashboard (`dashboard.py`)

Facts that bound the design (verified): `DashboardsCollection` is a local of Lovelace setup; every collection save
rewrites the whole storage file; the only reachable handle is `hass.data['lovelace'].dashboards[url]` (a
`LovelaceStorage` with `async_load/async_save`, `mode == 'storage'`).

Decisions:
- **No second collection writer, ever.** A test asserts the module never instantiates `DashboardsCollection`.
- **Creation is manual.** A missing `echo-home` raises repair issue `dashboard_missing` with the exact UI steps
  (Settings → Dashboards → New dashboard from scratch, URL `echo-home`); a reload then adopts the empty dashboard.
  The reviewer's alternative (an admin-browser action calling `lovelace/dashboards/create`) was considered and
  deferred: it adds UI and permission surface for a one-time step that the HA UI already does in four taps.
- **Overwrite requires proof of authorship by equality**, never by marker alone. Allowed when the current config
  equals (a) the last generated snapshot in `.storage/echo_experience.dashboard`, (b) the exact 0.5.1 `deploy.py`
  output for the current profiles (first-migration adoption), (c) the snapshot ignoring the version stamp, or (d) the
  dashboard is uninitialised (`ConfigNotFound`) or saved empty (only title/views/marker keys, no views). Any other
  read error → `dashboard_read_failed`, nothing written. Anything else → `dashboard_hand_edited` issue, untouched.
  Tests cover a marked-but-edited dashboard, an unmarked legacy dashboard, an unrelated dashboard, an empty saved
  dashboard, and an I/O failure on read.
- Backup (`.storage/echo_experience.dashboard_backups`, last five) is written before the dashboard save; a save
  failure leaves the snapshot unchanged and raises `dashboard_write_failed`.
- `mode != 'storage'` → `dashboard_yaml`, untouched. Option `manage_dashboard` (options flow, default on) skips all
  of it; changing options reloads the entry.

## 3. Stop route (`stop_route.py`)

Verified semantics: `get_agent_manager(hass).register_trigger(sentences, callback)` is what the `conversation`
trigger platform calls; callback is `async (ConversationInput, RecognizeResult) -> str | None`; HA runs every matched
callback and speaks the first non-`None`; all-`None` → "Done". A registered trigger therefore owns the sentence.

- Phrase list identical to the automation (`stop` + seven music phrases). No timer phrases: a sentence route cannot
  distinguish dismissing an alarm from cancelling a countdown; `echo_timer` does both with context.
- **Owner map built at load** from profiles and companion satellites (entity registry) and used for every request,
  so validated and executed mappings are the same object. Any device claimed twice → `route_conflict` issue, route
  not registered. Stricter than the old generator (which only rejected differing targets); stated in VOICE_STOP.md.
- Origin: `satellite_id` → registry device, else `device_id` (trigger-platform precedence).
- Owned device, bare `stop`: `dismiss_for_device(device, profile=p)` first; `dismissed` → "Timer stopped.";
  `unconfirmed`/`failed` → honest failure, music untouched; else music stop. Explicit music phrases skip the timer
  call. Music stop: `media_player.media_stop`, `blocking=True`, on the selected speaker; "Stopped." after return;
  service error → "I couldn't stop the music on <speaker name>." Music stop adds no navigation; the existing
  timer-dismiss path still publishes the timers view as in 0.5.x.
- Unknown device: real area required (`async_get_effective_area_id`), targets are enabled `sonos`-platform
  `media_player` entities whose own area (or device area fallback) matches; sorted; none → unchanged honest reply.
- Independent requests; no shared state beyond the read-only owner map.

**Exclusive ownership, honestly stated.** Automatic handover via state listeners cannot be atomic (HA attaches the
automation's triggers before writing its `on` state). So:
- On load: if the automation entity (found by `unique_id == '1757961047860'` on the live automation component's
  entities, not the state attribute) `is_on`, the route is not registered; `legacy_stop_automation` issue tells the
  user to disable/delete it and reload Echo Experience.
- While registered: every request re-checks the live automation object and returns `None` if it is on again (the
  automation then answers), with a warning to reload. A short overlap window exists during that switch; the issue
  text and VOICE_STOP.md say to make the change while idle.
- Rollback order documented: disable the entry, install 0.5.1 files, restart Core (an entry reload reuses the
  cached 0.6 module, so only a restart removes the route), then re-enable the entry and the automation.
- Startup: `after_dependencies: ["automation"]` in the manifest so the automation component's entities exist when
  the check runs.

## 4. Profiles, reload, prompt

`echo_experience.json` unchanged. New service `echo_experience.reload` (registered with
`async_register_admin_service`, so non-admin callers are refused) → `config_entries.async_reload`. Setup failures of
the frontend, dashboard or route each raise a translated `setup_failed_*` repair issue and clear on the next clean
setup; the new resource is created before the legacy one is deleted.
Reload resets selected speakers and ringing state (as today). The ringing-timer guidance is now in
`ExperienceAPI.api_prompt`. Fresh-install order (HACS → restart → JSON → empty dashboard → add integration) is in
the README; the config flow's file check is unchanged.

## 5. Packaging

`hacs.json` (`homeassistant: 2026.9.0` is a minimum, not a pin), manifest `documentation`/`issue_tracker`,
`brand/icon.png` + `icon@2x.png`, `translations/en.json` (mirrored to `strings.json`) with every repair issue key
(`test_translations_cover_every_issue_key_in_code`). HACS does not support private repositories; README offers
public repo or manual archive install. `requirements-dev.txt` pins `hassil`, `home-assistant-intents` and
`gazetteer-matcher` to the conversation manifest's versions so the matcher test is mandatory in CI (`CI=1` makes
a missing hassil fail rather than skip).

## 6. Tooling and CI

`tooling.py` holds `AUDIT`/`HERE`; `capture.py`, `verify_live.py`, `verify_routing.py` import it. Removed:
`deploy.py`, `stop_automation.py`, `dashboard.json`, `smbprotocol`. `automations/voice_music_stop.json` renamed
`legacy_voice_music_stop.json` for rollback reference. CI card commands use the package path.

## Behaviour changes

1. Music stop targets the selected speaker (playback's rule), not always the configured default; selection resets
   on reload/restart.
2. Shared voice-device ownership with identical targets is now rejected.

## Migration and rollback

In README ("Upgrading from 0.5.1", "Rollback to 0.5.1"): install, idle restart, resource swap and dashboard
adoption happen automatically; disabling the automation and reloading is the one manual step; rollback lists the
resource to delete, the `/local` resource to recreate, the backup store to restore from, and the order of route
withdrawal before re-enabling the automation.

## 0.6.1 addendum (live finding)

The live Echo runs Voice Satellite 2026.9.10 and Kiosk Satellite 2026.9.62, which together render finished-timer
alerts natively through `kioskSatellite.setVoiceTimerAlert`; no `.vs-timer-alert` element exists. The DOM-based
detection therefore reported "not ringing" and the server marked the alarm silenced while it kept sounding. 0.6.1
switches the card to Voice Satellite's own session object (`window.__vsSession.timer.alertActive` /
`.dismissAlert()`), which is authoritative for both rendering paths, keeps the DOM gesture as a fallback, and adds an
explicit "unknown" report so absence of evidence is never treated as silence.
